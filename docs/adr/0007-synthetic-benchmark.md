# ADR 0007：合成評測資料的設計

- 狀態：已採用（產生器版本 1，於任何對齊調校之前定稿）
- 日期：2026-11-20

## 背景

不能使用有版權的歌曲，所以評測資料必須自己合成，而且要有**精確的**逐字標準答案。規格 §10.1 的要求：
離線 TTS 逐字／逐詞合成後依已知位置拼接；加入長音、音高變化與 vibrato、快速段落、超過 8 秒的間奏；
用 numpy 合成伴奏並以 0／5／10／20 dB 混音；每種語言至少 10 首、每首 30–90 秒。

另一個同樣重要的要求在 §10.4：不得為了過關而修改測資。因此測資的設計必須在看到任何對齊結果之前決定，並且留下紀錄。

## 決定

### 聲音

- **TTS**：Kokoro-82M（模型與聲音皆為 Apache-2.0）。每個 token（一個漢字或一個英文詞）單獨合成並快取成檔案。
  選它的原因是授權乾淨（示範影片可以隨專案散佈）、CPU 上夠快、同一個聲音可以跨語言使用（中英混合的歌不會換音色）。
  piper 的新版是 GPL，espeak-ng 需要系統套件，都不採用。
- **「唱」出來**：用 WORLD 聲碼器（pyworld）把每個音節分析成音高、頻譜包絡與非週期成分，
  把音高換成旋律的音符，並把長度拉到節拍上的時值。只拉伸音節中段的母音（子音的起音與收尾保持原速），
  這比對整段做 time-stretch 更接近真人拉長音的方式。
- 旋律：五聲音階上的隨機遊走，音域以該聲音說話音高**往上一個四度**為中心（歌唱的音域比說話高）。
  每個音有小幅的起音滑音（−80～+40 cents）與 ±12 cents 的走音；時值 0.6 秒以上的音有 80% 機率加上 vibrato（5.5 Hz、±45 cents）。
- 節奏：72–128 BPM、4/4 拍。每行有「一般／快速（十六分音符，但不短於 140 ms）／慢速」三種之一；
  行尾最後一個字是長音（多 0.5–3 拍）。行內的斷句處（歌詞裡的空白或標點）有機率換氣停頓 0.5–1 拍。
- **連音**：一半的行是 legato——每個音延續到下一個音開始之後 45 ms 並交叉淡化，兩個字之間**沒有**掉到無聲。
  這一點是刻意的：如果每個字前面都有一小段靜音，起音偵測會變得太容易，數字會虛高。其餘的行是一般（時值的 90%）或斷音（70%）。
- 結構：前奏（≥4.5 秒）→ 主歌 → 副歌 → 間奏（>8 秒）→ 主歌 → **同一段副歌再唱一次** → 尾奏。
  重複的副歌是為了測試粗對齊會不會把兩段搞混。種子尾數為 3、6、9 的歌是對唱（男、女、合唱；合唱時兩個聲音同時唱）。
- 混音時人聲加上輕微的殘響（RT60 0.45 秒、比直達聲低 16 dB）。標準答案以**不含殘響**的乾聲為準。

### 伴奏與混音

- numpy 合成：和弦鋪底（6 個泛音的類鋸齒波，落在人聲音域）、bass、大鼓／小鼓／hi-hat，副歌的 hi-hat 加密；
  前奏、間奏、尾奏有一條旋律琶音（沒有人唱的時候仍然有「旋律樂器」）。
- 訊噪比的定義：人聲在「有聲音的取樣點」上的 RMS，對整首伴奏的 RMS。以 0／5／10／20 dB 四種比例混音。

### 標準答案

- 每個 token 的片段放在已知的取樣位置；起點與終點用同一個規則從**算繪後的片段本身**量出來：
  5 ms 的 RMS 包絡第一次（最後一次）達到該片段最大值的 5%（−26 dB）的位置。
  這就是本評測對「一個字從什麼時候開始」的定義，在產生器與指標裡只有這一個定義。
- 合唱的 token 取兩個聲音中較早的起點與較晚的終點。

### 資料分組

- `test`：每種語言 10 首（種子 1000–1009），× 4 種訊噪比＝120 個音檔。**只用來產生報告的數字。**
- `dev`：每種語言 4 首（種子 2000–2003）。所有可調的參數（對齊器的偏移校正、吸附距離、各種門檻）只用這一組調。
- 歌詞取自 `bench/kfbench/synth/corpus.py`：為本專案新寫的句子（中文 60 句、英文 60 句、中英混合 48 句），Apache-2.0。
  中文句子約一半帶有斷句用的空白。

### 可重現性

- 歌曲的一切（速度、調、結構、選哪些句子、每個字的節奏與旋律）都由 `(語言, 種子)` 決定，`plan_song()` 不需要 TTS，
  有單元測試確認每首歌都符合規格（長度、間奏、token 間距等）。
- TTS 片段快取在 `$KARAFORGE_HOME/bench/tts-cache`；`manifest.json` 記錄每個產生檔案的 SHA-256。
  換一台機器重新合成時，TTS 的浮點結果可能有極小的差異，manifest 可以用來確認資料是否與報告所用的一致。

## 定稿前做過的調整（都發生在任何評測之前）

1. 連音原本在字與字之間留有約 25 ms 的靜音 → 改成真正重疊交叉淡化（理由見上）。
2. 旋律原本以說話音高為中心 → 上移一個四度。
3. 每首歌的目標長度由 42–84 秒改為 50–88 秒，讓每首歌有比較多行。
4. 中文歌詞原本完全沒有空白，因此行內不會出現停頓 → 約一半的句子加上斷句空白。

之後若產生器有任何修改，必須提高 `GENERATOR_VERSION`、在這裡與 `PROGRESS.md` 記錄原因，並重新產生全部資料與報告。

## 已知的侷限（評測結果的解讀要考慮這些）

- 每個字是獨立合成的音節，字與字之間沒有真人演唱的協同發音；破音字一律用 TTS 對「單一個字」的預設讀音。
- TTS 的咬字比真人歌手清楚、音量穩定；伴奏是合成器音色，分離模型面對的不是它訓練時看過的那種音樂。
- 沒有和聲、疊唱、轉音與即興。
- 因此合成測資上的數字應該被視為**上限附近的參考值**；真實歌曲請用 `bench/real/` 自行評測。
