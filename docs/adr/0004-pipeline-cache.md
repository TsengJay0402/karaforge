# ADR 0004：管線快取——內容雜湊、run／publish 兩段式

- 狀態：已採用
- 日期：2026-11-20

## 背景

規格要求每個階段宣告輸入、參數、adapter 版本，快取鍵為 `sha256(輸入檔雜湊 + 參數 + adapter 版本)`，
Runner 只重跑受影響的階段。另外有兩個實務需求：

- 使用者在編輯器改了字的時間之後「匯出」，不可以因此重新對齊。
- 對齊結果要寫回 `project.json`，但 locked 的 token 絕對不能被覆蓋。

## 決定

- **鍵**：`sha256(階段名稱 + 階段版本 + 各輸入檔的內容雜湊 + 參數 + adapter 的 name@version + 其他輸入資料)`。
  「其他輸入資料」是指不在檔案裡的輸入，例如對齊階段的歌詞文字與 locked token 的時間。
  雜湊的是**內容**不是路徑，所以上游重跑但輸出位元組相同時，下游仍然命中快取。
  大檔的雜湊以 `(大小, mtime)` 為鍵記在 `cache/hashes.json`，不會每次重算。
- **兩段式**：
  - `run()`：昂貴的部分，把產物寫進 `cache/<stage>/<key>/`，回傳一個小的 JSON 結果；不碰 `media/` 與 `project.json`。
    先寫到 `<key>.partial-<pid>`，成功才改名，所以中斷或取消不會留下半成品。
  - `publish()`：便宜且冪等，把快取裡的產物「發佈」出去——硬連結到 `media/`、把資料合併進 `project.json`。
    不論快取命中與否，每次執行都會做。專案內容沒有變化時不存檔，`revision` 不會無故增加。
- **對齊階段的鍵不包含未鎖定 token 的時間**（那是它自己的輸出），只包含文字、手動讀音與 locked token 的時間。
  使用者鎖了幾個字再按「重新對齊」→ 鍵改變 → 以錨點重跑；什麼都沒改 → 命中快取。
- **匯出不帶相依**：`kf export` 與伺服器的匯出只執行 `subtitles` 與 `export` 兩個階段
  （`include_dependencies=False`），直接以專案目前的內容算繪，不會回頭觸發對齊。
- `--from <stage>` 強制該階段與其所有下游重跑。
- 每個階段保留最近幾份快取（依階段設定，分離結果因為檔案大只留 2 份），其餘依最近使用時間淘汰。

## 後果

- 評測可以在同一個專案上切換對齊參數做消融實驗，分離與辨識只會跑一次。
- `media/` 裡的檔案是快取的硬連結：不佔雙倍空間，但也不能就地修改（引擎本身不會這麼做）。
- 演算法改版時要記得調整階段的 `version`（對齊演算法用 `ALIGN_ALGORITHM_VERSION`），否則會讀到舊結果。
