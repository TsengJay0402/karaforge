# ADR 0008：匯入／匯出格式、專案格式 v2 與匯出的行為

- 狀態：已採用
- 日期：2026-11-21

## 背景

M3 要支援匯入 LRC／ASS（保留已有的時間）、匯出 ASS／LRC／增強型 LRC／SRT／UltraStar／專案壓縮檔，以及 MKV。
規格只列出格式名稱，以下是實作時必須自己決定的事。

## 決定

### 1. 匯入的時間有兩種，用不同的方式保存（專案格式升到 v2）

| 檔案裡有什麼 | 存到哪裡 | 之後對齊時 |
|---|---|---|
| **逐字**時間（增強型 LRC 的 `<mm:ss.xx>`、ASS 的 `\k`、UltraStar） | token 的 `start_ms`／`end_ms`，`source="import"`，並且 `locked=true` | 當成硬性錨點，不會被改掉 |
| 只有**逐行**時間（一般 LRC、SRT、沒有 `\k` 的 ASS） | 行的新欄位 `time_hint: [start_ms, end_ms|null]`，token 沒有時間 | 粗對齊直接用它當這一行的時間窗，不必靠語音辨識去找 |

為什麼逐字時間要鎖定：使用者匯入別人做好的逐字歌詞，最不想看到的就是按下「處理」之後被自動對齊覆蓋掉。
想重新對齊的人可以在編輯器裡解除鎖定。

為什麼逐行時間不直接攤到每個字上：一行的開始時間不等於每個字的時間，攤上去的數字是假的；
把它當成「這一行大概在這裡」的提示交給對齊器，才是它實際代表的資訊。

一個時間單位包含好幾個 token 時（例如把「你好」當成一個詞計時的檔案），時間平均分給各 token，
只有第一個 token（它的開始時間是確定的）被鎖定，其餘標成低信心，之後對齊可以修正它們。

`time_hint` 是新欄位，所以 `schema_version` 由 1 升到 2，並附上真正的遷移函式（v1 的每一行補上 `time_hint: null`）
與以規格書裡的範例檔寫成的遷移測試。

### 2. 每一種匯出格式都只產生「一個檔案」

`kf export --format <格式>` 與 Web 的匯出 API 共用 `karaforge.exporting.export()`；
檔案一律先寫到專案的 `exports/`，CLI 的 `--output` 是再複製一份到指定位置。

| 格式 | 檔名 | 說明 |
|---|---|---|
| `mp4` | `<名稱>.mp4` | H.264 + AAC，字幕燒進畫面 |
| `mkv` | `<名稱>.mkv` | 畫面不含字幕；ASS 軟字幕＋附加字型＋兩條音軌 |
| `ass` | `<名稱>.ass` | 與預覽、燒錄用的是同一份 |
| `lrc` | `<名稱>.lrc` | 每行一個時間；長停頓前加一個空的時間列，讓播放器在間奏時清掉歌詞 |
| `elrc` | `<名稱>.enhanced.lrc` | 每個 token 前一個 `<時間>`；token 之間有停頓時多寫一個結束時間 |
| `srt` | `<名稱>.srt` | 每行一個字幕；最短 0.5 秒，不與下一行重疊 |
| `ultrastar` | `<名稱>.ultrastar.txt` | 見第 4 點 |
| `kfproj` | `<名稱>.kfproj.zip` | `project.json` 與 `media/`；不含快取（可以重算）與 `exports/` |

多位演唱者時，LRC 用常見的 `M:`／`F:`／`D:` 行首標記（匯入時也認得）；只有一位演唱者時不加。

### 3. 匯出時指定的解析度不會寫回專案

`--res 720p` 只影響這一次匯出。原本的做法是先改 `project.json` 再匯出，但那會讓「匯出」這個唯讀動作改變文件的
revision——在 Web 編輯器開著的時候會造成不必要的儲存衝突。

### 4. UltraStar

- UltraStar 的時間單位是 beat，一拍長 `15 / BPM` 秒。`#BPM` 用歌曲的 tempo 連續加倍到一拍不超過 50 ms
  （沒有 tempo 時用 300），`#GAP` 是第一個字的開始時間；所以匯出後再讀回來，每個時間的誤差不超過一拍。
- 音高（相對於 C4 的半音數）由 pYIN 在人聲軌上估計：取每個 token 時間範圍內有音高的影格的中位數。
  沒有音高的字（很短的字、氣音）沿用同一行前一個字的音高。pYIN 的結果快取成一個獨立的管線階段（`pitch`），
  只有匯出 UltraStar 時才會執行。專案還沒有人聲軌時，所有音符寫成 C4（能唱，但沒有計分用的音高）。
- 空白放在下一個音節的開頭（UltraStar 的慣例），讀回來時再搬回前一個 token 的結尾。
- 只產生 `.txt`，標頭裡的 `#MP3`／`#VIDEO` 寫成 `<名稱>.<原始媒體的副檔名>`；CLI 會提示使用者把媒體檔放在旁邊。
  不自動複製媒體檔，是為了維持「一種格式一個檔案」，也避免在 `exports/` 裡與影片輸出撞名。

### 5. MKV

- 第一條音軌依 `--audio`（預設伴唱），第二條是另一種：伴唱 ↔ 原唱。音軌標題是「伴唱 / Karaoke」「原唱 / Original」，
  第一條設為預設。
- 字幕是 ASS 軟字幕（標題 `KTV`，預設開啟），算繪計畫用到的每個字型檔都以附件嵌入，
  所以在沒有安裝這些字型的電腦上用 mpv／VLC 播放，看到的字和燒錄版一樣。
- 畫面是背景（含底部漸層加暗）但不含字幕。

### 6. 匯入 ASS 時認得三種腳本

1. KaraForge 自己匯出的：`Comment` 事件、效果欄是 `karaoke` 的那些行帶有 `\k` 逐字時間與演唱者，可以原樣讀回（有往返測試）。
2. 其他工具做的卡拉 OK 字幕：`Dialogue` 裡的 `\k`／`\kf`／`\ko`／`\K`。
3. 一般字幕：每個 `Dialogue` 變成一行，帶逐行時間提示。向量繪圖（`\p`）事件會被略過，同一時間、同樣文字的重複事件（多個圖層）只取一次。

## 後果

- 匯入逐字 LRC 後不需要任何處理就能直接匯出影片或其他格式（token 已經有時間）。
- 舊的 v1 專案開啟時在記憶體中升級，下一次儲存時才寫成 v2，並保留 `.bak`。
- 匯出 UltraStar 需要 `librosa`（核心相依，已具備）；第一次匯出多花約每分鐘音訊 1 秒的 pYIN 計算。
